Simple to self-host · v1.0 · open source (ISC)

One engine. Unlimited databases.

DataCore is a lightweight, self-hosted panel that runs a single instance of PostgreSQL, MySQL, MariaDB or MongoDB — then provisions as many isolated databases with per-database users as you need. Everything is configured by environment variables.

> features

Built to be boringly easy to run

A panel, not a platform. One process, real drivers, and everything you need fits in a single .env.

Run once, deploy many

Start a single instance of each engine. Deploy unlimited logical databases from the panel, each isolated with its own credentials — no container per database.

Per-database users

Add or revoke users scoped to a single database from the UI. No SSH into containers, no hand-written SQL, no shared admin credentials leaking around.

Configured by .env

Hosts, ports, superusers and the panel password all come from environment variables. No admin console, no settings database, no account to create.

No Docker socket

The panel talks to engines over TCP with real drivers — pg, mysql2, mongodb, mariadb. It never mounts the Docker socket and can’t touch your host.

Engine health at a glance

Live status cards show running, stopped or error for every enabled engine the moment it’s configured.

Credentials on day one

Deploy a database and get a working connection string back immediately. Passwords are shown once, then masked with a reveal toggle.

> how it works

From zero to a new database in minutes

No daemon, no sidecar, no platform APIs. Just a panel that knows its SQL.

  1. 01

    Compose up

    docker compose up -d runs the panel and every engine in a single project. Or run the panel on the host.

  2. 02

    Configure once

    Set DATACORE_PASSWORD plus per-engine *_HOST / *_SUPERUSER / *_SUPERPASSWORD. Done.

  3. 03

    Deploy

    Pick an engine and a name. DataCore provisions the database, creates the user and returns the credentials exactly once.

  4. 04

    Manage

    Open a database’s detail page for its connection string. Add or revoke per-database users any time.

> faq

Questions, answered

How is this different from running one container per database?

Each engine is a single server process. Databases are logical units with their own users and privileges — not separate containers. Fewer moving parts, far less RAM, and no orchestrator stitching containers together.

Does it need the Docker socket or root access?

No. DataCore is a plain Node process that connects to engines over TCP with normal database drivers. It never mounts the Docker socket and can’t manage host containers.

Which engines are supported?

PostgreSQL, MySQL, MariaDB and MongoDB. Each one appears in the panel as soon as its *_HOST environment variable is set.

Do I still host the engines myself?

Yes. DataCore manages databases and users inside engines you already run — locally, in Docker Compose, or on a remote host. It provisions databases, not servers.

How does security work?

Credentials live in environment variables, sessions are signed, superuser passwords stay out of your clients’ hands, and connection passwords are validated to keep out metacharacters. You self-host, so nothing leaves your machine. Review it before you trust it in production.

Is it free?

Yes — open source under the ISC license. Self-host it anywhere a Node process runs.
